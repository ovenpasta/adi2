# Internationalization (I18N)

Adi provides a gettext-compatible internationalization system for translating
UI strings at runtime. Translations are registered in-memory at startup from
generated Ada packages (compiled from `.po` files), and resolved at UI build
time via simple function calls.

```
src/adi-i18n.ads              -- Public API
src/adi-i18n.adb              -- Implementation (canonicalization, fallback)
src/adi-i18n-catalog.ads/adb  -- Internal catalog storage
src/adi-i18n-plural.ads/adb   -- Plural formula evaluator
src/adi-sdl-locale.ads/adb    -- SDL locale auto-detection
```

## Quick Start

```ada
with Adi.I18N; use Adi.I18N;
with My_Translations;

procedure My_App is
begin
   --  1. Register all translations (generated from .po files)
   My_Translations.Register_All;

   --  2. Set language (or omit to auto-detect from OS)
   Set_Language ("fr");

   --  3. Use T() in your UI code
   Label.Set_Text (T ("Hello"));           --  => "Bonjour"
   Label.Set_Text (T ("Unknown"));         --  => "Unknown" (passthrough)
end My_App;
```

## Language Management

```ada
procedure Set_Language (Lang : String);
function Get_Language return String;
```

- `Set_Language` accepts any locale format: `"fr"`, `"pt_BR"`, `"pt-BR"`,
  `"PT-br"`. The input is **canonicalized** (lowercased, hyphens replaced
  with underscores) before storage.
- If `Set_Language` is never called, `Get_Language` auto-detects from
  `SDL_GetPreferredLocales` on first access.
- Language is global state. Changing it affects all subsequent `T()` / `Tn()`
  calls but does not retroactively change previously returned strings (the
  model is non-reactive — `T()` returns a plain `String` snapshot).

## Simple Translation

```ada
function Translate (Msg_Id : String) return String;
function T        (Msg_Id : String) return String renames Translate;
```

Looks up `Msg_Id` in the current language catalog. Returns `Msg_Id` unchanged
if no translation is found (passthrough fallback).

### Context Disambiguation

```ada
function Translate (Context : String; Msg_Id : String) return String;
function T        (Context : String; Msg_Id : String) return String renames Translate;
```

When the same English string has multiple meanings (e.g. "Open" as a verb vs.
adjective), use context to select the right translation:

```ada
Register ("fr", "Open", "Ouvrir",  Context => "menu");
Register ("fr", "Open", "Ouvert",  Context => "adjective");

T ("menu", "Open")       --  => "Ouvrir"
T ("adjective", "Open")  --  => "Ouvert"
T ("Open")               --  => "Open" (no match without context)
```

## Plural Translation

```ada
function Translate_Plural
  (Msg_Id : String; Msg_Id_Plural : String; N : Natural) return String;
function Tn
  (Msg_Id : String; Msg_Id_Plural : String; N : Natural) return String
  renames Translate_Plural;
```

Selects the correct plural form based on `N` and the language's plural
formula. `Msg_Id` is the singular (also the lookup key), `Msg_Id_Plural`
is the English plural (used as fallback).

```ada
Tn ("file", "files", 0)   --  fr: "fichier"  (French: 0 is singular)
Tn ("file", "files", 1)   --  fr: "fichier"
Tn ("file", "files", 5)   --  fr: "fichiers"
```

A contextual variant is also available:

```ada
function Translate_Plural
  (Context : String; Msg_Id : String; Msg_Id_Plural : String;
   N : Natural) return String;
```

### Plural Formulas

Formulas use C-like syntax with variable `n`. Common examples:

| Language | N_Plurals | Formula |
|----------|-----------|---------|
| English  | 2 | `n != 1` |
| French   | 2 | `n > 1` |
| Polish   | 3 | `n == 1 ? 0 : n % 10 >= 2 && n % 10 <= 4 && (n % 100 < 10 \|\| n % 100 >= 20) ? 1 : 2` |
| Arabic   | 6 | (complex — see gettext docs) |

The formula evaluator supports: `? :`, `||`, `&&`, `==`, `!=`, `<`, `>`,
`<=`, `>=`, `+`, `-`, `*`, `%`, `!`, parentheses, integer literals, and `n`.

When no formula is registered for a language, the English default (`n != 1`)
is used. When no plural forms are registered for a key, fallback returns
`Msg_Id` for `N = 1` and `Msg_Id_Plural` otherwise.

## Explicit-Language Translation

These variants accept an explicit language code and **do not read or modify
the global language state**. Useful for language switcher UIs, side-by-side
previews, or querying multiple languages simultaneously.

```ada
function Translate_Language
  (Language : String; Msg_Id : String) return String;
function TL
  (Language : String; Msg_Id : String) return String
  renames Translate_Language;

function Translate_Language
  (Language : String; Context : String; Msg_Id : String) return String;

function Translate_Plural_Language
  (Language : String; Msg_Id : String; Msg_Id_Plural : String;
   N : Natural) return String;
function TnL
  (Language : String; Msg_Id : String; Msg_Id_Plural : String;
   N : Natural) return String
  renames Translate_Plural_Language;

function Translate_Plural_Language
  (Language : String; Context : String; Msg_Id : String;
   Msg_Id_Plural : String; N : Natural) return String;
```

Example:

```ada
Set_Language ("fr");
TL ("de", "Hello")   --  => "Hallo" (German)
T ("Hello")           --  => "Bonjour" (global is still French)
```

Short aliases (`TL` / `TnL`) are provided for the no-context forms only.
Context variants use the full name to keep call sites self-documenting.

## Locale Fallback Chain

When looking up a translation, Adi tries:

1. **Exact canonical language** — e.g. `pt_br`
2. **Base language** (strip region) — e.g. `pt`
3. **Passthrough** — return the original `Msg_Id`

This means `Set_Language("fr_CA")` will find translations registered under
`"fr"` if no `"fr_ca"`-specific entry exists. Fallback does not cross
language boundaries — `"de"` will never fall back to `"fr"`.

## PO File Workflow

### Writing .po Files

Use standard GNU gettext `.po` format:

```po
# French translations for My App
#
msgid ""
msgstr ""
"Content-Type: text/plain; charset=UTF-8\n"
"Plural-Forms: nplurals=2; plural=n > 1;\n"

msgid "Hello"
msgstr "Bonjour"

msgctxt "menu"
msgid "Open"
msgstr "Ouvrir"

msgid "file"
msgid_plural "files"
msgstr[0] "fichier"
msgstr[1] "fichiers"
```

- The `Plural-Forms` header is required for languages with plural translations.
  If omitted, the English default (`nplurals=2; plural=n != 1;`) is assumed.
- The language code is derived from the filename: `fr.po` => `"fr"`,
  `pt_BR.po` => `"pt_BR"`.
- Entries marked `#, fuzzy` are skipped (not included in generated output).
- Empty `msgstr` entries are skipped.

### Compiling .po to Ada

```bash
python3 tools/po_to_ada.py \
  --output-dir examples/generated/ \
  --package-name My_Translations \
  fr.po de.po pt_BR.po
```

This generates `my_translations.ads` (spec with `procedure Register_All`)
and `my_translations.adb` (body with all `Register` / `Register_Plural` /
`Register_Plural_Formula` calls).

### Build Integration

`tools/build_examples.sh` runs `tools/generate_example_translations.sh` before
compiling, which invokes `po_to_ada.py` for example `.po` files. Generated files
go to `examples/generated/` which is already in `Source_Dirs`.

For custom projects, add a similar script or call `po_to_ada.py` directly
before `gprbuild`.

## XML UI Integration

When using the XML UI system (`tools/xml_to_ada.py`), pass `--i18n` to wrap
translatable string attributes with `T()` calls in the generated Ada code.

```bash
python3 tools/xml_to_ada.py input.xml \
  --output-dir out/ --package-name My_UI --i18n
```

### Which strings are wrapped

The widget grammar (`tools/widgets.xml`) marks certain attributes as
`translatable="true"` — typically user-visible text like button labels,
label text, and placeholder strings. Non-translatable attributes (CSS
classes, enum values, numeric fields) are never wrapped.

### Context directives

- **File-level context**: `<i18n context="my-screen"/>` at the top of the XML
  sets a default context for all strings in the file.
- **Per-attribute context**: `text-i18n-context="menu"` overrides the
  file-level context for a specific attribute.
- **Suppression**: `i18n="false"` on a widget disables wrapping for all its
  attributes.

```xml
<adi>
  <i18n context="home-screen"/>
  <window title="My App">
    <!-- Uses file context: T("home-screen", "Welcome") -->
    <label text="Welcome"/>

    <!-- Override context: T("menu", "Open") -->
    <button text="Open" text-i18n-context="menu"/>

    <!-- Suppressed: plain "Debug" literal -->
    <label text="Debug" i18n="false"/>
  </window>
</adi>
```

Without `--i18n`, all strings are plain Ada literals (no `Adi.I18N`
dependency). This is the default for examples that don't need translation.

## Registration API

These are typically called from generated packages, not application code:

```ada
procedure Register
  (Language : String; Msg_Id : String; Msg_Str : String;
   Context  : String := "");

procedure Register_Plural
  (Language : String; Msg_Id : String; Forms : Plural_Forms;
   Context  : String := "");

procedure Register_Plural_Formula
  (Language : String; N_Plurals : Positive; Formula : String);

procedure Clear;
```

`Register_All` (in the generated package) calls these in bulk at startup.
`Clear` removes all translations and resets the language — mainly used
in tests.

## Example: Material Demo

The material demo showcases i18n with French and German translations:

```
examples/i18n/fr.po               -- French .po source
examples/i18n/de.po               -- German .po source
examples/generated/i18n_example_translations.ads/adb  -- Generated Ada
examples/xml/material_demo.xml     -- XML UI (compiled with --i18n)
examples/material_demo.adb         -- Wiring code
```

```bash
# Build
alr exec -- gprbuild -j0 -P examples/examples.gpr -XEXAMPLE_KIND=material_demo

# Run
./examples/bin/material_demo --lang fr    # French
./examples/bin/material_demo --lang de    # German
./examples/bin/material_demo              # Auto-detect from OS
```

## Testing

```bash
alr exec -- gprbuild -j0 -P tests/tests.gpr -XTEST_KIND=i18n_test
./tests/bin/i18n_test
```

Tests cover: empty catalog passthrough, simple translation, locale
canonicalization (case, hyphens), fallback chain, context disambiguation,
plural formula evaluation, explicit-language APIs, global state isolation,
and contextual plural fallback.

## API Reference

### `Adi.I18N`

| Function | Description |
|----------|-------------|
| `Set_Language (Lang)` | Set global language (canonicalized) |
| `Get_Language` | Get current language (auto-detects if not set) |
| `T (Msg_Id)` | Translate using global language |
| `T (Context, Msg_Id)` | Translate with context |
| `Tn (Msg_Id, Msg_Id_Plural, N)` | Plural translation |
| `Tn (Context, Msg_Id, Msg_Id_Plural, N)` | Plural with context |
| `TL (Language, Msg_Id)` | Translate in explicit language |
| `Translate_Language (Language, Context, Msg_Id)` | Explicit language with context |
| `TnL (Language, Msg_Id, Msg_Id_Plural, N)` | Explicit language plural |
| `Translate_Plural_Language (Language, Context, Msg_Id, Msg_Id_Plural, N)` | Explicit language plural with context |
| `Register (Language, Msg_Id, Msg_Str, Context)` | Register a translation |
| `Register_Plural (Language, Msg_Id, Forms, Context)` | Register plural forms |
| `Register_Plural_Formula (Language, N_Plurals, Formula)` | Register plural formula |
| `Clear` | Reset all translations and language |
