What is going on

The triangle is drawn by OpenGL into a texture this application owns. Adi issues no GL call and never destroys the texture: it is handed the texture's name and blits it where the layout put the widget.

Nothing here is about OpenGL

The widget is Adi.Widget.Texture_View, and it takes a texture from any API SDL can build its renderer with: OpenGL, GLES2, Vulkan, Direct3D 11 and 12, or the SDL GPU API. GL, GLES and Vulkan name a texture with an integer; the rest hand over a pointer. Metal is the one exception, because SDL adopts a CVPixelBuffer there rather than a texture.

So ask for a renderer with Prefer_Render_Driver and read back Render_Driver to learn what you actually got. A texture from the wrong API is refused, and the only other symptom is an empty widget.

Why it composes

The view overrides one hook, Render_Content, and is otherwise a widget like any other: sized by CSS, clipped by its parent, drawn in tree order. The panel writes plain variables and the GL callback reads them on its next pass, so neither side reaches into the other.

Sharing a context with SDL

This is the part that bites. SDL's renderer behaves as though it owns the whole GL state, so call SDL_FlushRenderer on the way in and on the way out: it drops the state SDL has cached, and the state worth dropping is what you just changed.

Then save and restore everything you touch. Scissor above all — SDL leaves GL_SCISSOR_TEST enabled with a rectangle in window coordinates, which will happily clip your drawing into a texture that has nothing to do with the window. Leaving it off instead is just as bad: the widgets drawn afterwards stop being clipped.

Redrawing

Adi composites only what changed, and a texture's name does not change when its contents do. The producer says so itself, by calling Invalidate after each frame it finishes.

Keeping the corners

The rounded border belongs to the frame around the view, not to the view itself. A texture is blitted as a plain rectangle, and Adi clips a widget to a rectangle too, so a radius on the view would leave square corners poking out of it.

Why the bindings are hand-written

Adi_GL is a demo-sized binding, not a general one. The thick Ada bindings model GL objects as owned Ada values with their own idea of what is bound, which is exactly the assumption SDL breaks by binding behind their back: none of them can read back GL_CURRENT_PROGRAM or GL_FRAMEBUFFER_BINDING to restore it.

The split inside it is worth copying. OpenGL 1.1 entry points are imported directly, because Windows exports exactly those and no more. Everything newer is resolved through SDL_GL_GetProcAddress, which also guarantees it comes from the context SDL made current.
